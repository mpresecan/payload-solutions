title: Payload Emails
description: Declare transactional emails in code, let editors write the copy in the admin, and send them with one typed call.
---

Automated emails — verification, password reset, invitations, receipts — are usually hard-coded templates that need a developer and a deploy to change a sentence. Payload Emails turns each one into a document in the Payload admin, without giving up type safety at the call site.

You declare an email once in TypeScript: its key, the input callers pass, the variables editors may use, how input becomes variables, and default copy. The plugin keeps one document per definition where non-developers edit the subject and body, preview it with sample data, send themselves a test, and switch non-critical emails off.

```ts
await payload.emails.send('welcome', { input: { user, url } })
```

## Defining an email

```ts
import { defineEmail, populate } from '@payload-solutions/plugin-emails'

export const welcome = defineEmail({
  slug: 'welcome',
  label: 'Welcome',
  trigger: 'users afterChange hook (operation: create)',
  group: 'Auth',
  audience: 'user',
  inputSchema: [
    { name: 'user', type: 'relationship', relationTo: 'users', required: true },
    { name: 'url', type: 'text', required: true },
  ],
  variables: {
    'user.name': { description: 'Display name', example: 'Ada Lovelace' },
    'user.email': { example: 'ada@example.com' },
    url: { type: 'url' },
  },
  resolve: async ({ input, payload }) => {
    const user = await populate(payload, 'users', input.user)
    return { 'user.name': user.name || user.email, 'user.email': user.email, url: input.url }
  },
  to: ({ variables }) => variables['user.email'],
  defaults: {
    subject: 'Welcome to {{site.name}}, {{user.name}}',
    body: `
Hi {{user.name}},

Thanks for creating an account on [{{site.name}}]({{site.url}}).

<Button label="Open your dashboard" url="{{url}}" />
`,
  },
})
```

Register the definitions with the plugin and Payload does the rest:

```ts
plugins: [emailsPlugin({ emails: [welcome, passwordReset] })]
```

## The design is a React Email template

The look of every email is a React Email component in your code — colours, spacing, the wordmark, the shell. Editors supply the words; the template supplies the design, so nothing drifts.

```tsx
export const BrandTemplate: EmailTemplate = ({ children, footer, settings }) => (
  <Html>
    <Head />
    <Body style={{ backgroundColor: '#0b0b0c' }}>
      <Container style={{ maxWidth: 600 }}>
        <Section style={{ backgroundColor: '#fff', borderRadius: 12, padding: 40 }}>{children}</Section>
        {footer}
      </Container>
    </Body>
  </Html>
)
BrandTemplate.styles = { button: { backgroundColor: '#ff5a1f' }, text: { fontSize: '15px' } }
```

`children` is the editor's copy, rendered to React Email elements with variables already filled in. HTML and plain text come from the same tree, so they never disagree.

## In the admin

- **Transactional Emails** — one document per definition, with drafts. Editors change the subject, preheader, body (Lexical, with a Button block), recipients and the enabled switch. A typo such as `{{user.nmae}}`, or a variable broken up by bold, fails validation with the list of allowed variables.
- **Variable chips** in the sidebar (click to copy) and an About panel showing the key, when it fires, and its audience.
- **Preview & test** — a form generated from the email's own input schema (relationships offer real documents to pick), the rendered email in a sandboxed iframe (desktop/mobile, HTML/plain text, draft/published, locale), the resolved recipients and variables, and a test send to any address.
- **Email Settings** — sender and reply-to, admin recipients, site name and URL, the footer, and a Template tab that previews the design and tells editors to contact their developers to change it.
- **Email Log** (opt-in) — every send with status, recipient and reason.

## Typing

The plugin hooks into `payload generate:types`, so every email key, its input and its variables land in `payload-types.ts`:

```ts
export interface Config {
  emails: { welcome: EmailWelcome; 'password-reset': EmailPasswordReset }
}
export interface EmailWelcome {
  input: { user: number | User; url: string }
  variables: { 'user.name': string; 'user.email': string; url: string }
}
```

An unknown key, a missing input field, a wrong select value or an incomplete `resolve` are compile errors. Before the first generation the types fall back to permissive ones, so a fresh project still compiles.

## Code and database

Code owns metadata; the database owns copy. On init the plugin seeds a document for every new definition from its defaults, refreshes stored metadata when the definition changes, renames documents listed in `previousSlugs`, and flags documents whose key is gone as orphans. A deploy never overwrites what an editor wrote, and metadata refreshes never create versions or unpublished drafts.

Sending goes through Payload's configured email adapter, so Resend, Nodemailer or console logging all work unchanged. Delivery can optionally run through Payload Jobs for retries and scheduling.
